Daily workflow

After enroll: select a lab, flash, monitor, and move between tracks without full re-init.

Every lab day

rbdev doctor                 # optional preflight
rbdev run 00                 # sticky project from workshop root is OK
rbdev run 00 --monitor       # build + flash + serial monitor

Project resolution order: explicit --project → walk up from cwd (CMakeLists.txt + main/) → sticky default_project from .rbdev.toml.

Lab selection with rbdev run

CommandResult
rbdev runList labs in the resolved project (exit 0)
rbdev run 00Rewrite main/main.c, then build + flash
rbdev run ex06Same; accepts 06, ex06, etc.
rbdev run 00 -mBuild + flash + monitor
rbdev run 00 --select-onlyOnly rewrite main/main.c (no build)
Steps inside a lab rbdev run NN picks the lab. Many device labs also have steps selected inside exNN.c (see that lab’s README). There is no --step flag in the current CLI.

TrackFolderTypical run range

Switch track — do not full re-init

Port, board, IDF path, and PATH shims from the first init stay.

# Prefer: cwd wins over sticky
cd labs\rtos-labs
rbdev run 00

# Or one-shot from workshop root
rbdev run 00 --project labs/rtos-labs

# Optional: update sticky default + set-target for that track
rbdev init --project rtos-labs -y

Port and board day-to-day

rbdev config --show
rbdev config --port COM17 --board ws28p
rbdev config --port /dev/cu.usbmodemXXXX --board es3c28p

After switching boards, run rbdev reconfigure (or idf.py fullclean then build) so CMake picks up -DBOARD=.

Build / flash without changing lab id

rbdev build
rbdev flash
rbdev monitor
rbdev reconfigure          # after adding new exNN sources

Students can ignore these and stay on rbdev run. They are thin wrappers around idf.py with sticky board/port.
