Full ESP-IDF workflow via idf.py

After init, every Espressif idf.py action is available without export.ps1 / export.sh. rbdev does not duplicate every verb as its own subcommand.

Parity contract Small classroom surface (init, doctor, config, run) + transparent gateway: idf.py … shim or rbdev idf -- …. The shim loads IDF env, injects -DBOARD=, and exports sticky ESPPORT when you do not pass -p.

How to invoke

# After init (PATH shim) — preferred in class
idf.py build
idf.py menuconfig
idf.py fullclean

# Explicit passthrough (always works if rbdev is on PATH)
rbdev idf -- build
rbdev idf -- menuconfig
rbdev idf -- -p COM17 erase-flash

Examples for class

# Interactive config UI
idf.py menuconfig

# Wipe build tree then rebuild
idf.py fullclean
idf.py build

# Erase chip (uses sticky COM if set)
idf.py erase-flash

# Size report after a successful build
idf.py size
idf.py size-components

# App-only flash
idf.py app-flash

# Explicit port wins over sticky
idf.py -p COM6 flash monitor

# Same via rbdev passthrough
rbdev idf -- fullclean
rbdev idf -- --version
Working directory Run these from a lab project folder, or from the workshop root after init (sticky project). If resolution fails, cd labs/device-labs first.

Anti-goal

Do not expect first-class rbdev menuconfig, rbdev fullclean, etc. Those stay on the Espressif CLI so the workshop tracks upstream docs and does not drift.
