Getting started

From clone to a working sticky config in one enroll step: rbdev init.

Prerequisites

NeedNotes
Workshop repo firmware-esp32-s3-workshop with lib/ and include/ present
ESP-IDF (Path A) Course install on the PC (v6.1). init discovers it — no activate script
Board + USB Waveshare ws28p (default) or Ternion es3c28p
Editor Cursor / VS Code recommended (committed .vscode/settings.json puts rbdev on PATH)

1. Clone and open the workshop root

git clone https://github.com/drsanti/firmware-esp32-s3-workshop.git
cd firmware-esp32-s3-workshop

Open this folder (the one that contains rbdev/ and labs/) in Cursor. Do not open only a subfolder, or PATH settings will not apply.

2. First terminal: run init

In Cursor, a new terminal already has the shipped binary on PATH via .vscode/settings.json. Prefer plain rbdev init. 

# Preferred (Cursor, workshop root)
rbdev init

# Fallback if rbdev is not found yet
.\rbdev\windows\rbdev.exe init          # Windows
./rbdev/mac/rbdev init                  # macOS
./rbdev/linux/rbdev init                # Linux
Project prompt Choose device-labs unless the instructor names another track. Scripted classroom: rbdev init --port COM6 --board ws28p --project device-labs -y

What init does

  1. Finds ESP-IDF (sticky path → env → Espressif registry → common folders)
  2. Repairs the Espressif Python venv if needed (install.bat / install.sh)
  3. Picks serial port (menu / auto) and one lab track
  4. Writes gitignored .rbdev.toml (paths use /)
  5. Runs idf.py set-target esp32s3 in the selected project
  6. Installs stable shims under LocalAppData / ~/.local/share/rbdev/bin and updates user PATH
  7. May auto-cd into the project (shell wrappers / PowerShell profile)

3. Open a new terminal

PATH and idf.py shims load in new terminals. Then verify: 

rbdev doctor
rbdev run 00

PATH helpers compared

SituationWhat to use
Cursor / VS Code, workshop root open Nothing extra — .vscode/settings.json (do not delete)
After successful init User PATH + %LOCALAPPDATA%\rbdev\bin (Windows) or ~/.local/share/rbdev/bin
Windows outside Cursor Double-click start-here.cmd (PATH for that cmd window only)
rbdev still missing Call rbdev/<os>/rbdev with an explicit path
start-here.cmd does not replace init It only opens cmd with rbdev\windows on PATH and prints reminders. You still type rbdev init / rbdev run 00 yourself.

Non-interactive init (CI / TA scripts)

rbdev init --project device-labs --port auto --board ws28p -y
rbdev init --project device-labs --port COM17 --board ws28p -y --skip-install
rbdev init --project rtos-labs -y --skip-set-target   # rare

Useful init flags

FlagMeaning
-y / --yesNon-interactive; auto-picks port if unset
--project device-labsSkip project menu
-p COMx / --port autoSerial port or best-effort USB pick
--board ws28p|es3c28pBoard SKU
--idf-path …Force a specific ESP-IDF tree
--target esp32s3Chip (workshop default)
--skip-installDo not run IDF install scripts
--force-installAlways run IDF install
--skip-set-targetSkip set-target
--no-add-pathDo not modify user PATH
